# Brain MCP tools

Canonical v3 input schemas and descriptions: [tool-contracts.v3.json](tool-contracts.v3.json), generated by scripts/generate-tool-docs.ts. Runtime checks also validate live authorization, ownership, source audience, quota and version.

This document describes the 29 tools registered by `src/brain/lifecycle.ts`. Description strings and JSON input schemas below were generated from the current registry; output schemas document the current implementation, rather than claiming that an MCP outputSchema is advertised.

Every call uses the bearer token’s user, brain and assistant identity. Supplying IDs belonging to another brain does not grant access. Read tools require `brain:read`; write tools require `brain:write`. Reasoning and jobs also need read access to assemble context. Saved-context retrieval is deterministic, requires no AI approval or model request, and works with read-only grants. Read-only requests may update session tracking and retrieval receipts without generating stored memory. Optional AI rollups require model access and writable authority.

Successful results carry JSON in the first MCP text block and a short human summary in another text block. Every JSON result is an object with `trailer` and, on an eligible session’s first call, optional `briefing` and structured `continuity`. Explicit `resume` returns that packet at the top level, including within an existing derived session. Array results are wrapped as `{items:[...],trailer,...}`. Errors may instead be MCP error content; missing/invalid credentials and insufficient tool scopes are HTTP401/403 challenges.

JSON Schema cannot express every application check. Assistant labels are lowercase letters, digits and hyphens, at most32 characters; `all` is reserved for note broadcasts. `mark_notes_read` requires a nonempty ID list or `all:true`. Date inputs must be ISO8601 timestamps with offsets. A successful write is attributed to the calling assistant. Snapshots are retained until explicit user deletion or purge; no retention pruning runs.

Output references use the shared schema catalog at the end of this file. It is a documentation URN, not a hosted endpoint. Optional extra record properties may be added without breaking these contracts.

This retrieves saved context, not a transcript of unsaved speech. Call resume at the start of a new call or chat. Save memory during the call. Use think for reasoning, do for longer tasks. Speak naturally, never JSON; weave in briefing. Call end_session before goodbye. Writes retain attribution, evidence and visibility.

Restores saved state even when nothing changed or a new chat reuses the same token within 30 minutes. No model request or hosted-AI approval is needed. The default serialized packet budget is 16,000 UTF-8 bytes; omitted material sets truncated. Source receipts are bounded to 40, and content without a receipt is not returned. A normal first tool touch may return this same shape inside continuity; explicit resume returns it directly. Starting a new project intentionally skips prior-project recovery on its first touch.

| Field | Meaning |
| --- | --- |
| project | Current id, title, goal, version and status, plus confirmed_constraints, confirmed_decisions, proposed_items, open_questions, unfinished_tasks and review_flags. Item entries include id, title, content, status, confirmation, revision and needs_review; pending corrections may be withheld when their sources are unavailable. |
| current_session | Available saved tool request/answer material from the existing derived session. Includes id, last_activity_at, summary and summary_source=saved_tool_activity; does not claim a native call boundary. |
| previous_session | Most recent eligible same-label saved session material: id, last_activity_at, summary, summary_source, and optional snapshot_id. Summary source is auto_snapshot, manual_snapshot or saved_tool_activity. |
| nightly_update | Latest authorized saved overnight diff: id, created_at, optional generated_at, kind=diff and a summary of at most 100 words. It is labeled as a historical review; current facts and decisions still take precedence. |
| saved_snapshot | Fallback standalone snapshot with id, title, kind, agent_label, created_at and content. It is not claimed to be the prior native call. |
| recent_notes / facts / open_work / waiting_results | Visible saved notes and facts, unresolved work, and completed/partial job result material. Waiting jobs are acknowledged only after successful external delivery, not internal context assembly. |
| source_refs / source_audience | Actual delivered record receipts and their intersected audience. Deleted, restricted or unavailable source chains cannot be recovered through an older summary. |
| saved_context / resume_count / resumed_at | Whether saved content was returned, and optional persistent retrieval receipt. Empty retrieval and failed tool responses do not count; the receipt is recorded only after successful response assembly. A receipt proves tool delivery, not native Sesame memory or transcript synchronization. |

Current canonical facts, constraints and decisions take precedence over historical summaries. Voice-created project constraints and decisions remain clearly marked proposals until owner confirmation, but are still available to resume. Project selection uses an explicit ID, a visible saved bookmark or the sole unambiguous visible active project. Use projects_list to select another project. No unsaved speech is recoverable.
